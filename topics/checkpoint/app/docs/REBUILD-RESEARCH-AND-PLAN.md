# Recognition and reflection rebuild

Research and implementation decision, 6 November 2026. This replaces the previous 20-second/30-second reflection proposal. The user reports incorrect recognition, slow character changes and confusing interface flow. No participant interviews were conducted for this rebuild. Earlier persona answers remain fictional design inputs.

## What was wrong

Source inspection found that the default reflection ignored most pretrained category output and reduced movement to positive/tense. It required 12 usable seconds across a 15-second span, with a 30-second minimum display hold. A check-in then pinned the default character indefinitely. These rules were design guesses, not requirements of the circumplex model. Model initialization and inference also shared the camera-reading thread, so slow ML could interrupt preview and return stale frames.

The useful product outcome is: notice a legible reflection while playing, decide whether it fits, and review one's own pleasantness/energy check-ins afterwards. A webcam cannot verify an inner feeling, diagnose frustration, or reliably identify all 43 words. Better geometry alone does not solve that inference problem.

## Three interaction alternatives

1. Direct puppet: most immediate but overreacts to speech, chewing and isolated movements; useful as a diagnostic Movement test, poor default for the user's requested reflection.
2. Long held mood badge: visually stable but misses laughter and remains stale after change. The current implementation demonstrated this failure.
3. **Selected: responsive expression reflection with a separate recent trend.** Short evidence dwell plus quality gates changes an authored Nori pose; a longer rolling window supplies a trend sentence. Check-ins and CMA remain a separate task. Trade-off: ambiguous expression may remain neutral-looking rather than forcing an impressive but wrong label.

## Implementation plan and acceptance

1. Fix capture: preview continues during cold model initialization and slow inference. One latest frame replaces older pending input. Reject inference results older than one second; stop/join the inference worker on pause. Preserve Windows DirectShow fallback and camera error recovery.
2. Fix recognition integration: use pretrained category scores in the default view. Require a clear leading score and complementary visible features for anger/sadness/surprise/disgust/fear/contempt. A brow furrow, open mouth or teeth alone cannot establish an emotion. Smile movement can support a smile-like reflection when categories are uncertain; disagreement yields an uncertain state.
3. Fix timing/behaviour: time-based adaptive feature filtering; three observations and a proposed 0.45-second dwell (neutral return 0.65 seconds). No 30-second lock. Proposed target is under 1.25 seconds for a clean sustained signal at eight analyses/second, excluding cold initialization. One-frame spikes must not switch the pose. A four-second time-weighted trend is displayed separately. These are engineering defaults requiring target-user evaluation, not established psychological thresholds.
4. Fix flow/UI: one Start face tracking action explicitly enables local tracking. Default Live reflection, optional Movement test and My check-in have distinct labels. Nori is the visual focus; inspection details are secondary. A manual report cannot freeze the live face. Pausing or loss/occlusion returns to a flat neutral appearance with a clear unavailable label. Reduced motion keeps feedback functional.
5. Preserve reporting: reported CMA, timestamps, sample counts and PDF remain grounded in player check-ins. Automatic visual transitions never become durations of felt emotion. Phone receives the same reflected state; no camera image is exported.
6. Verify before release: replay onset/offset, jitter, isolated spikes, disagreement, hand occlusion, loss, recovery and manual-report separation. Compare actual videos using the same clips/crops for both candidates; record per-class errors, abstention and CPU latency. Run native/phone flow, inspect screenshots, then Windows package/updater smoke tests. Publish on topic/checkpoint with a new version and downloadable release.

## Evidence still needed after this repair

The four-actor acted-video set is an exploratory regression comparison, not target-context validation. Do not train or tune against its labels and then call that a test. Next useful study: consented local webcam sessions with varied lighting/skin tones/glasses and natural game reactions, participant check-ins, independently annotated visible expressions, subject-separated evaluation, coverage/abstention and false anger per hour. Add actual game/window FPS and CPU/power measurements on the user's Windows computer. Evaluate whether the companion helps rather than distracts; do not infer intervention benefit from a screenshot or synthetic replay.

No personal emotion-photo collection is required to use this build. Neutral calibration is optional and stays in memory. YouTube gameplay may help screen-event prototyping, but unlabelled streamer faces are not ground truth for felt emotion and were not used to train this repair.

## Measured model decision

The matched comparison completed on 208 clips (2,080 sampled frames per model). B0 and B2 both achieved 62.5% clip-level argmax accuracy. B2 macro F1 was 0.607 versus B0 0.603; anger recall fell from 0.563 to 0.375. Median full face-pipeline CPU time was 47.3 ms for B2 versus 28.5 ms for B0 on this Linux worker, with p95 57.9/37.1 ms. These are exploratory measurements on four actors, not Windows/gamer performance or confidence-gated display accuracy.

**Retain B0 for this release.** The larger model did not improve overall accuracy, missed more anger, and was slower. Installing a larger model would not address the demonstrated integration/timing faults. The raw evaluation and per-class errors are in `artifacts/rebuild-model-comparison.json`; reproduce with `python -m ml.compare_rebuild_models --data <separately-sourced-dataset> --candidate <provider-enet_b2_8.onnx>`. Candidate URL: https://raw.githubusercontent.com/sb-ai-lab/EmotiEffLib/main/models/affectnet_emotions/onnx/enet_b2_8.onnx. Candidate weights are not bundled.

The deterministic replay at eight samples/second switched to a sustained smile in 0.50 seconds, tense expression in 0.625 seconds, neutral return in 0.875 seconds and recovered after occlusion in 0.50 seconds. Previous code took 12/22 seconds on the smile/tense segments in that trace and failed to return neutral within five seconds. These measure logic response after input delivery, excluding camera, cold model startup and animation convergence. At 12Hz the old 180-item history could never span its required 15 seconds; the rebuild also removes that sampling-rate failure. Full transitions at 4/8/12Hz: `artifacts/reflection-replay.json`.

A second matched test evaluated EmotiEffLib `mbf_va_mtl` (MobileFaceNet, 112px RGB, provider normalization, first eight expression logits only; its extra VA outputs were deliberately unused). It scored 60.58% with macro F1 0.591 versus B0 62.5% / 0.603. Anger recall rose slightly to 0.594 but precision fell to 0.826 from B0 1.0; median full-pipeline time was 32.0 ms versus 29.3 ms for B0 in that run. It is not selected: the overall trade-off did not justify a default change. Record: `artifacts/rebuild-mobileface-comparison.json`. Official model: https://github.com/sb-ai-lab/EmotiEffLib/tree/main/models/affectnet_emotions/onnx.

Actual realtime processing of seven actor04 clips exercised camera-independent preview, face/hand geometry, category inference, default reflection and CMA isolation. Several acted expressions were unclear or missed; this is a smoke check, not successful recognition validation. The first iteration also produced smile-like output on the neutral speech clip. Inspection led to requiring cheek or model support for a smile; this is a semantic guard, not a new accuracy result. The updated run still has substantial uncertainty. Raw aggregate results: `artifacts/reflection-video-smoke.json`. No raw frames/recordings are redistributed.
